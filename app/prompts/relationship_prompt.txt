# NGUYÊN TẮC CHUNG

- Chỉsửdụngthông tin cótrong transcript và candidate events đượccungcấp.
- Khôngđượctựtạothêm fact, event, decision, task, owner, deadline, problem hoặc relationship.
- Khôngxácđịnhtrạngtháicuốicùngcủacuộchọp ở bướcnày.
- Khôngloạibỏ candidate event chỉvì event đócóvẻđãlỗithời.
- Phảigiữnguyên ý nghĩatheotrìnhtựthờigiancủacuộchộithoại.
- Mọi relationship phảicócăncứtừ transcript.
- Khôngsuyra relationship chỉvìhai event chứacáctừgiốngnhau.
- Nếu relationship khôngrõràng, khôngđượctựđoán.
- Một event cóthểcó relationship vớinhiều event khác.
- Khôngđượcnhómcác event thuộcnhữngchủđềđộclậpvàocùngmột thread.
- Imlặnghoặckhôngphảnđốikhôngđồngnghĩavớichấpnhận.

- Event xuấthiệnsaukhôngtựđộngthaythế event trước.
- Khi khôngđủbằngchứngđểxácđịnh relationship, khôngtạo relationship đó.
# QUY TẮC VỀ REASON

Mọi relationship trong output phảicóđầyđủ 4 field:

## Địnhnghĩacácloại Relationship

### SAME_TOPIC

Hai event nóivềcùngmộtchủđềhoặcđốitượng.

"Hoàn thiện API login."


### UPDATES

Một event xuấthiệnsaucậpnhậtthông tin của event trướcnhưngkhôngthaythếhoàntoànđốitượngđangđượcnóitới.

Vídụ:

Deadline = ThứSáu

evt_002:
Deadline đổi sang Thứ Hai

### CONTRADICTS

Hai event đưarathông tin hoặcquanđiểmmâuthuẫnvớinhau, nhưng transcript chưathểhiện event nàochínhthứcthaythếhoặcbácbỏ event cònlại.

Vídụ:

Minh:
ThứSáuchắckhôngkịp.

Hai event này CONTRADICTS nhau.

Khôngtựđộngcoiđâylà REJECTS.


### ACCEPTS

Một event thểhiệnviệcchấpnhậnrõràngmột proposal, request hoặcphươngántrướcđó.

Vídụ:

evt_001:
"Hay dùngPayOS?"

evt_002:
"Ok, chọnPayOS."

Relationship:

evt_002 ACCEPTS evt_001


### REJECTS

Một event thểhiệnviệcbácbỏrõràngmột proposal, request hoặcphươngántrướcđó.

Vídụ:

evt_001:
"Tôiđềxuấtdùng Stripe."

evt_002:
"Khôngdùng Stripe."

Relationship:

evt_002 REJECTS evt_001


### SUPERSEDES

Một event mớithaythếmộttrạngthái, phươngán, decision, task definition hoặc value trướcđó.

Event cũkhôngcònđạidiệnchotrạngtháihiệntại.

Vídụ:

"Chúng ta dùng Stripe."

"Thôibỏ Stripe, chuyển sang PayOS."

### BLOCKS

Một event đạidiệncho problem hoặc obstacle đangtrựctiếpngăncảnhoặctrìhoãnmột task hoặchoạtđộngkhác.

Vídụ:

event_type = TASK_CREATED
content = "Deploy production"

evt_002:
event_type = OBSTACLE_RAISED
content = "Chưacó production credential"

Relationship:

evt_002 BLOCKS evt_001


### RESOLVES

Một event xuấthiệnsaugiảiquyếtrõràngmột problem, obstacle hoặc open issue đãđượcnêutrướcđó.

Vídụ:

evt_001:
"API login đanglỗi."

evt_002:
"API login đã fix xong."

### DEPENDS_ON

Một event cầnmột task, condition, dependency hoặckếtquảkhácxảyratrướcthìmớicóthểtiếptục.

Vídụ:

## Nguyêntắcchung

- ACCEPTS phảicóbằngchứngrõràngvềsựđồng ý.
- Khôngsuyra ACCEPTS từsựimlặng.
- REJECTS yêucầucóhànhđộngtừchối, khôngchỉlà feedback tiêucực.
- SUPERSEDES yêucầucósựthaythế, khôngchỉđơnthuầnlàđưarathêmmộtphươngán.
- UPDATES giữnguyênđốitượnggốcnhưngthayđổimộtthuộctínhhoặctrạngthái.
